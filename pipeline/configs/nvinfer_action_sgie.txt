# The exported action_classifier.onnx has a static batch=1 input axis
# (confirmed via onnx_to_engine.py: "ONNX is fully static — skipping
# --minShapes/--optShapes/--maxShapes"), not the dynamic batch the
# ModelSpec's min/opt/max_batch=1/16/32 assumed. A batch-size=16 engine
# request against a batch=1-only engine fails checkBackendParams()
# ("Backend has maxBatchSize 1 whereas 16 has been requested") on every
# deserialize attempt, forcing a full TensorRT rebuild on every pipeline
# start. Matches the same static-batch reality already documented for
# nvinfer_rfdetr.txt/onnx_to_engine.py's rfdetr ModelSpec.

# PGIE (nvinfer_rfdetr.txt) is a fine-tuned 2-class detector — 0=person,
# 1=handbag (see COCO_CLASS_MAP in pipeline.py) — NOT the 80-class COCO
# set. Action classification (walking/carrying/dumping/etc) only makes
# sense for the person class; the old generic COCO id list (0;1;2;3;5;7
# = person/bicycle/car/motorcycle/bus/truck) never matched this PGIE's
# actual output and would have run the SGIE on stray handbag detections
# (id 1) while never seeing the vehicle ids it was written for.
